## 2. Carry Forward: Brand Promise, Visual Choices & Two Honest Persuasion Elements

* **Brand Promise & Character ([Pearson Archetypes](https://carolspearson.com/about/the-pearson-12-archetype-system-human-development-and-evolution)):** Primary **Creator** (building interactive Figma prototypes, deployed web apps, and playable games) paired with **Sage** (explaining user logic, comparing non-AI alternatives, and separating observed evidence from assumptions).
* **Visual Choices ([V&A Modernism](https://www.vam.ac.uk/articles/what-was-modernism) vs. [Postmodernism](https://www.vam.ac.uk/articles/what-is-postmodernism)):** Restrained **Modernist** layout for the portfolio shell, case study tables, and readable résumé (high-contrast typography, generous whitespace, scannable headings), while letting the embedded project screenshots (`/screenshots/idea-thinker.png`, `/screenshots/the-reckoner.png`, `/screenshots/save-the-apple.png`) show expressive creative personality.
* **Two Honest Persuasion Elements ([Cialdini Principles](https://cialdini.com/principles)):**
  1. **Verifiable Authority & Friction-Free Proof ([Issue #4](https://github.com/JivExperimenters/Jivitesh-Portifolio/issues/4)):** Every project card pairs a public, no-login URL (Figma, Netlify, Base44, itch.io, GitHub) with an **in-repository screenshot** so reviewers never hit a sign-in wall (and login-gated workspaces like *AppAssemblers* are explicitly archived via screenshot).
  2. **Honest Trustworthiness (Separating Planned Checks from Observed Results):** Clearly labels student prototypes vs. production systems and explicitly marks the 5-peer *Idea Thinker* usability walkthrough as a **planned check** rather than claiming unmeasured user results.

## 6. React Documentary Idea Applied to My Portfolio Site

After watching [React.js: The Documentary (CultRepo / Honeypot)](https://www.youtube.com/watch?v=8pDqJVdNa44), I am applying two core ideas from the film directly to my portfolio architecture:

* **UI as a Function of Explicit State (Not Manual Patching):** In the documentary, Jordan Walke explains that traditional front-end UI code breaks down on **state management**—manually finding and patching DOM nodes when something changes—and that React solves this by rendering the UI cleanly from explicit state (`if empty -> show A`, `if loading -> show B`, `if unhelpful -> show C`, just like the Like button example).
  * **Example on My Site:** In my *Idea Thinker* case study (`/work` and `/research/career`), I apply this state-driven model to the **Guided Thinking (MCQ)** flow so the UI renders three explicit states: (1) **Empty State** (3 tappable starter chips), (2) **Loading State** (*"Mapping 3 angles from your MCQ choices..."*), and (3) **Unhelpful-Result Recovery State** (the inline *"Refine 1 Step Back / Switch to Movie Twist"* bar).
* **Separating Concerns by Reusable Component:** As discussed around React's component model (`ProjectCard` / `FilterBar`), organizing HTML, styling, and interaction logic around a **reusable component** rather than duplicated pages keeps the portfolio consistent and testable.
  * **Example on My Site:** On `/work` and `/`, each project (`Idea Thinker`, `Offline TV`, `T-Shirt SQLite Store`, `ClubThread Quotes`, `The Reckoner`, `itch.io Games`) follows one consistent **Project Card pattern** (*Title, Role/Contribution Badge, In-Repo Screenshot, Public No-Login Link, and Scope Label*).
